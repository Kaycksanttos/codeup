# CodeUp — aprenda SQL, Python e Análise de Dados na prática

App web instalável no celular (PWA). Escreve código de verdade no navegador, corrige no servidor,
tem contas, 3 cursos (Python e SQL com 3 níveis de 30 lições cada; Excel com o nível Básico de 30 lições e 3 provas), 2 checkpoints e uma prova final por nível, XP/vidas/sequência. **Cada lição tem duas atividades: 1) executar (escrever o código) e 2) ler (entender o que um código pronto faz).** O dono escolhe pelo painel quais cursos ficam ativos no aplicativo. **Gratuito para o aluno, mantido por anúncios (Google AdSense).**

## Testar tudo do começo (modo teste)

`npm run teste` (vazio) ou `npm run teste:demo` (com alunos de exemplo) sobe uma cópia do app em http://localhost:3100 com dados novos, sem tocar no seu `data.json` nem no banco de verdade. O painel fica em `/admin` (chave `admin-teste`), o e-mail de confirmação e o "esqueci a senha" abrem na hora e a faixa laranja tem o botão **Começar do zero**. O roteiro completo está em **TESTAR.md**.

## Curso de Excel (novo)
- **Excel Básico:** 30 lições + checkpoints (depois da 10 e da 20) + prova final, tudo em planilha de verdade na tela: o aluno digita fórmulas (`=SOMA(B2:B6)`, `=SE(A1>10;"ok";"não")`, `=PROCV(...)`), preenche para baixo, usa referências absolutas `$`, e vê o resultado na hora.
- **Em português do Brasil:** nomes de função em português, separador `;`, vírgula como decimal (aceita sem acento: `SE`, `SOMASE`, `MEDIA`…). O motor é próprio (`public/xl.js`), sem `eval`.
- **Correção** (`xlcheck.js`): compara o resultado de cada célula pedida com o gabarito e confere se a fórmula foi usada (não vale digitar o número pronto: o servidor troca os números da planilha e confere se o resultado acompanha). Quando erra, a tela mostra célula a célula o que faltou (vazia, erro de sintaxe, valor diferente, número fixo).
- **Limites honestos:** em casos raros o motor pode diferir do Excel de verdade (arredondamentos, formatos de data); PROCX só existe no Excel 365/2021; o Excel Intermediário/Avançado, o Power BI e DAX e a Análise de Dados aparecem como “Em breve”.
- Conferir o conteúdo: `npm run check:excel` (valida as 33 atividades com as respostas oficiais).

## Duas atividades por lição (executar + ler)
- **No mapa** cada círculo de lição tem um **anel de duas metades**: a 1ª metade acende quando o aluno **executa** (escreve o código) e a 2ª quando **lê** (entende o que um código pronto faz). Só com as duas metades completas o anel fecha, a lição conta como concluída e a próxima abre.
- **Ordem fixa:** 1º executar, 2º ler. A atividade de ler só abre depois de executar (o servidor devolve 409 `lock:'ex'` se tentar antes). Errar na leitura não gasta vida nem pontos: aparece uma dica e dá para tentar de novo.
- **XP e diamantes:** o XP da lição é dividido entre as duas (metade na 1ª, metade na 2ª; `xpParts` em `server.js`), cada metade paga só uma vez; diamantes: +2 ao executar e +3 ao ler (total +5, como antes).
- **Formatos da atividade de ler** (misturados): escolher a alternativa certa (o que o código mostra, em que ordem, qual é o erro…), **digitar** a resposta curta, e no SQL ver as tabelas do exemplo; no Excel, uma planilha pronta com a pergunta. O gabarito **nunca** vai ao navegador (só as opções, embaralhadas por aluno); a correção é no servidor.
- **Quem já tinha concluído lições antes** continua com elas concluídas (as duas atividades contam como feitas, sem pagar XP de novo). Recomeçar um nível apaga as duas atividades.
- **Conteúdo:** `content/rd-*.js` (uma entrada por lição, escrita com os helpers de `content/rdh.js`: `mc`, `ty`, `mo`, `to`, `me`). `npm run check:ler` roda cada código (Python no `python3`, SQL no sql.js, Excel no motor `public/xl.js`) e confere que a resposta marcada é a que o código realmente produz; os 5 itens de "conceito" (sem saída para executar) não têm essa prova automática. Ao mexer em SQL, rode o comando inteiro: ele regrava `content/seed-tables.json`.

## 1) Rodar no seu computador (VS Code)
1. Instale o Node.js 18 ou superior (nodejs.org).
2. Abra o terminal **na pasta onde está o `package.json`** (no VS Code: botão direito na pasta → Abrir no Terminal) e rode: `npm install`. Se aparecer a pasta `node_modules` ali dentro, deu certo. O `sql.js` também vem copiado em `vendor/sql/`, então o SQL funciona mesmo sem o `npm install`; o instalador cuida do resto (Express etc.). Ao iniciar com `npm start`, o terminal mostra **"Correção de SQL no servidor: ATIVA"**; se aparecer **FALHOU**, rode `npm install` de novo nessa pasta e reinicie (enquanto isso o servidor confere o SQL pelo resultado enviado pelo navegador, como já faz no Python sem Linux). Na lição, o aluno escreve, vê o resultado do código na hora e só toca em **Concluído** para ser avaliado.
3. Copie `.env.example` para `.env` (no teste, use `ADS_PREVIEW=1` para ver as caixas de anúncio).
4. `npm start` → abra http://localhost:3000 (precisa de internet: SQL e Python carregam de uma CDN).
5. Para conferir tudo: `npm test`.

Na recuperação de senha, sem e-mail configurado, o link aparece no terminal do servidor.

## 2) Colocar no ar (Render.com — o caminho mais simples)
**Passo a passo completo, para quem nunca publicou: `DEPLOY-RENDER.md`.** Resumo:
Você precisa de: uma conta no GitHub, uma no Render e um domínio (opcional no início).
1. Suba a pasta `codeup` para um repositório no GitHub (o `.gitignore` já protege o `.env` e os dados).
2. No Render: **New → Blueprint** → escolha o repositório (ele lê o `render.yaml`).
3. Preencha as variáveis pedidas (veja o `.env.example`): `BASE_URL`, `COMPANY_NAME`, `CONTACT_EMAIL`, e-mail e (depois) os anúncios.
4. O `render.yaml` cria o site **e um banco PostgreSQL** (planos pagos: site ≈ US$ 7/mês e banco ≈ US$ 6/mês, conforme a tabela de preços do Render). Os dados dos alunos ficam no banco, com backup do Render; sem banco, os usuários sumiriam a cada reinício.
5. Aponte seu domínio em Settings → Custom Domains. O HTTPS é automático.
Funciona igual em Railway, Fly.io ou qualquer VPS com Docker (`Dockerfile` incluso). Use a variável `DATABASE_URL` com o endereço do seu Postgres (Supabase e Neon têm plano grátis). Sem `DATABASE_URL`, o app usa o arquivo `data.json` (monte um volume em `/data`).
**Importante:** rode **uma única cópia** do servidor (os dados ficam em memória e são gravados a cada segundo). Se já tinha alunos no `data.json`, ele é importado para o Postgres automaticamente na primeira vez.
Obs.: o `render.yaml` usa os nomes de plano atuais do Render (`0.5c-512mb` e `0.1c-256mb`) e foi conferido contra a documentação, mas não foi aplicado na plataforma real; se o Render reclamar de algum campo, crie o serviço manualmente (Docker + um PostgreSQL e a variável `DATABASE_URL`).
Obs. 2: o app foi testado em modo produção contra um PostgreSQL de verdade (cadastro, correção de Python e SQL, e dados mantidos depois de reiniciar). A imagem Docker (Alpine) não pôde ser construída aqui; no primeiro deploy olhe o log: devem aparecer `Dados em: PostgreSQL` e `Correção de Python no servidor: ATIVA`.
Obs. 3: o plano de 512 MB aguenta bem o começo (o app usa ~120 MB parado e cada correção de Python com pandas ~65 MB, limitadas a 2 ao mesmo tempo). Se o painel do Render mostrar a memória perto do limite, suba o plano do site.

## 3) Anúncios (Google AdSense)
O app é gratuito e ganha dinheiro com anúncios. **Você liga tudo pelo painel do dono, sem mexer no servidor:** `/admin` → **Ajustes** → cartão **Anúncios (Google AdSense)**. Sem nada configurado, nenhum anúncio aparece.
1. Coloque o site no ar com domínio próprio e as páginas **Termos** e **Privacidade** (já existem). O AdSense só aprova sites públicos, com conteúdo e política de privacidade.
2. Em adsense.google.com, cadastre o site. A análise leva de alguns dias a algumas semanas.
3. No painel, cole o **ID do editor** (`ca-pub-...`, em AdSense → Conta → Informações da conta) e ligue. Dá para colar o código inteiro que o Google gera: o painel separa os números. Vale na hora, sem reiniciar. A página inicial passa a levar a meta tag `google-adsense-account` (no AdSense, verifique o site pelo método **Metatag** ou **ads.txt**).
4. Depois de aprovado: em AdSense → Anúncios → Por bloco de anúncios, crie um **display responsivo** e cole o número do `data-ad-slot` no campo **ID do bloco**. Sem ele o app não desenha os quadros. Deixe os “Anúncios automáticos” desligados no AdSense.
5. O arquivo `/ads.txt` é gerado sozinho com o seu ID (abra `https://SEU-DOMINIO/ads.txt` para conferir). Quem prefere variáveis de ambiente ainda pode usar `ADSENSE_CLIENT` e `ADSENSE_SLOT`: o que for salvo no painel vale mais, e “Voltar ao padrão do servidor” devolve o valor das variáveis.
6. Onde aparecem: início, cursos, desafios, perfil e tela de fim de lição, sempre com o rótulo “Publicidade”. **Nunca** durante lição ou prova (melhor para o aluno e exigido pelas regras do AdSense contra cliques acidentais).
7. Aviso de cookies: o aluno **não escolhe** o tipo de anúncio. Os anúncios são sempre **não personalizados** (o app pede isso ao Google) e carregam direto; o aviso mostra só um botão “Entendi” (e some durante lição e prova). Anúncios personalizados exigiriam o consentimento do aluno, por isso ficam fora. Isso ajuda com a LGPD, mas **peça a um advogado para revisar**; se tiver público na Europa, use também a mensagem de consentimento do próprio AdSense (Privacidade e mensagens).
7. Regras do AdSense: nunca clique nos seus próprios anúncios nem peça para outros clicarem; o Google bloqueia a conta.
Não consegui testar com o Google real aqui (sem acesso à rede deles); no primeiro dia olhe o console do navegador por erros de CSP. Se algo for bloqueado, a política está em `server.js` (`ADS_HOSTS`).

## 4) E-mail — necessário para a recuperação de senha funcionar
Sem um serviço de e-mail configurado, o link de redefinição **só aparece no terminal do servidor** e o aluno que esquecer a senha não recebe nada. Escolha uma opção:
- **Resend (mais simples):** crie a conta em resend.com → *Domains* → adicione e verifique o seu domínio (ele mostra os registros DNS para você colar no seu provedor de domínio) → *API Keys* → crie uma chave. No ambiente: `RESEND_API_KEY=re_...` e `MAIL_FROM="CodeUp <no-reply@seu-dominio.com.br>"`.
- **SMTP** (Brevo, Amazon SES, Gmail com senha de app…): `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` e `MAIL_FROM`.
Sem domínio próprio verificado, a maioria dos provedores só entrega para o seu próprio e-mail ou cai no spam — configure o domínio antes de lançar.

**Como funciona a recuperação:** “Esqueci minha senha” → o aluno recebe um e-mail com um botão (link válido por 1 hora, uso único) → cria a nova senha e **já entra no app**. Por segurança: a resposta é a mesma exista ou não a conta, são no máximo 3 e-mails por hora por endereço, um pedido novo invalida o link anterior, todos os outros aparelhos são desconectados e o aluno recebe um aviso “sua senha foi alterada”. Quem entrou só com Google também pode criar uma senha por esse caminho (ou em Perfil → *Criar senha*). Logado, o aluno troca a senha em Perfil → *Alterar senha*.
**Se o e-mail de algum aluno não chegar** (spam, endereço errado), gere o link você mesmo e envie por WhatsApp: abra o **Painel admin** (seção 5b), entre no aluno e use **Gerar link de nova senha** — o link aparece na tela, é só copiar e enviar por WhatsApp.

## 4b) Login com o Google
1. Acesse console.cloud.google.com, crie um projeto (ou use um existente).
2. **APIs e serviços → Tela de permissão OAuth**: tipo *Externo*, preencha nome do app, e-mail de suporte, e publique o app (*Em produção*) — assim qualquer pessoa pode entrar. Só pedimos nome e e-mail.
3. **Credenciais → Criar credenciais → ID do cliente OAuth → Aplicativo da Web.** Em *Origens JavaScript autorizadas* adicione `https://seu-dominio.com.br` (e `http://localhost:3000` para testar). Não precisa de URI de redirecionamento.
4. Copie o **ID do cliente** para `GOOGLE_CLIENT_ID` e reinicie. O botão “Continuar com o Google” aparece sozinho nas telas de entrar e criar conta.
Como funciona: o Google entrega um token ao navegador, o servidor confere a assinatura e o e-mail verificado e cria a conta (no primeiro acesso a pessoa precisa aceitar os Termos). Se já existir uma conta com o mesmo e-mail, as duas são vinculadas.

## 5) Dia a dia
- **Como o curso funciona:** o aluno escolhe Python ou SQL (pode estudar a outra depois; o progresso é separado). Cada curso de programação tem 3 níveis (Básico, Intermediário, Avançado; o Excel tem o Básico por enquanto) com 30 lições em sequência. **Cada lição tem 4 explicações** (o que é, para que serve, como se faz e qual o retorno esperado), mostradas na tela de teoria ("o que é" fica dentro do balão do personagem). **A cada 10 lições há uma prova**: o aluno monta, sozinho, uma consulta/programa completo com o que aprendeu (sem dica, sem solução, sem teoria). **Checkpoint (depois da lição 10 e da 20):** 2 chances; se errar as duas, **volta 5 lições** (6 a 10, ou 16 a 20) para relembrar; só passando abre a lição 11 / 21. **Prova final do nível (depois da lição 30):** uma tarefa com tudo desde o começo, 3 chances; passou = libera o próximo nível (+50 × nível de XP na 1ª vez); errou as 3 = **volta 10 lições** (21 a 30). Os pontos já ganhos são mantidos e não se ganha pontos duas vezes. Um erro que impede o código de rodar (digitação) não gasta chance. Provas já vencidas podem ser treinadas sem perder nada. Tudo isso é imposto no servidor (`/api/submit`); o gabarito, as dicas e a solução das provas nunca vão ao navegador (só, depois de um erro, o resultado esperado).
- **Editar lições e provas:** os arquivos ficam em `content/` (`py1.js`…`sql3.js` têm as lições; `info-*.js` têm as 4 explicações de cada lição; `checkpoints.js` tem as provas). Depois de mudar uma atividade Python, rode `npm run build:content` (ele roda a solução no `python3` e atualiza o gabarito em `content/expected.json`) e depois `npm test`. Mudar o número de chances ou de lições que voltam: constantes `CHANCES` e `BACK` no topo de `lessons.js`. Ao mudar lições de um nível que já tem alunos, o progresso deles continua pelo `id` da lição; não reutilize `id`s para conteúdo diferente.
- **Exemplos de SQL:** pode escrever o `example` e a `solution` em uma linha só; o app organiza sozinho na tela (uma parte do comando por linha — SELECT, FROM, JOIN, WHERE... —, recuo nas subconsultas e CTEs) e mostra a legenda "Como ler" com o que cada parte faz. Isso é o arquivo `public/fmt.js` (não altera o texto do comando). Se você já escrever o exemplo em várias linhas, ele aparece exatamente como você escreveu.
- **Seus dados:** `COMPANY_NAME`, `CONTACT_EMAIL`.
- **Números do negócio e gestão dos alunos:** o **Painel admin** em `/admin` (seção 5b logo abaixo).
- **Backup:** com Postgres, é do próprio provedor (confira se está ligado). No modo arquivo, 1 por hora na pasta `backups/` (guarda os últimos 72); copie-a de vez em quando para fora do servidor.
- **Confirmação de e-mail:** quem cria conta com e-mail e senha recebe um link (vale 48 h). Pode estudar sem confirmar. Login com Google já entra confirmado. Só funciona se o e-mail do passo 4 estiver configurado; sem ele, as contas entram direto.
- **Python corrigido no servidor:** ao enviar uma lição ou responder uma prova, o servidor roda o código do aluno num processo isolado (sem rede, sem acesso a arquivos, sem subprocessos, com limite de tempo e memória) e compara a saída; o que o navegador diz ter impresso é ignorado. Precisa de `python3` + pandas no servidor (o `Dockerfile` já instala). Se não houver python3, o app avisa no log e volta ao modo antigo.

## 5b) Painel admin (só para você)
Abra **`https://seu-site/admin`** (no seu computador: `http://localhost:3000/admin`) e entre com a chave de administrador — ou, se preferir uma entrada fixa, com **e-mail e senha**:

**Entrada fixa com e-mail e senha (o jeito mais simples, sem autenticador):** no `.env` do seu computador (ou em *Environment* no Render) escreva
```
ADMIN_EMAIL=seu@email.com
ADMIN_PASSWORD=uma-senha-longa-so-sua
```
e **reinicie o servidor** (feche o terminal com `Ctrl+C` e rode `npm start` de novo: o `.env` só é lido quando o servidor liga; ele é procurado na pasta do projeto, ao lado do `server.js`, mesmo que você ligue o servidor de outra pasta). Se a tela de entrada ainda pedir só a chave, o servidor que está aberto é o antigo: feche-o e ligue de novo. A tela do painel passa a pedir **E-mail** e **Senha** (o e-mail não diferencia maiúsculas; use 16+ caracteres na senha). A senha vale exatamente como a `ADMIN_KEY` (se você definir as duas, **vale só a `ADMIN_PASSWORD`**: uma `ADMIN_KEY` antiga deixa de abrir o painel e as rotas de script); sem `ADMIN_EMAIL` a tela volta a pedir só a chave. O erro é sempre "E-mail ou senha incorretos", sem dizer qual dos dois errou, e **o e-mail e a senha ficam só nas variáveis do servidor — nunca escreva isso em arquivo que vai para o GitHub** (o `.env` não vai no zip nem no repositório). O autenticador de 6 dígitos (abaixo) é opcional e continua desligado até você ligar. Se ele já estiver ligado e você não consegue usá-lo, crie `ADMIN_2FA_OFF=1`, reinicie e entre só com e-mail e senha (veja "Perdeu o celular?" abaixo).

**No Render:** a chave já é criada sozinha — abra o seu serviço → **Environment** → `ADMIN_KEY` → *Reveal* e copie (pode trocar por uma sua).

**Como ligar em outro lugar:** defina `ADMIN_KEY` com uma senha longa (16+ caracteres) — no `.env` do seu computador ou nas variáveis do Render — e reinicie. Sem `ADMIN_KEY` o painel fica **desligado** em produção (e qualquer endereço `/api/admin/...` responde 404, como se não existisse). No seu computador, se você não definir nada, o servidor gera uma chave sozinha e **mostra no terminal** quando inicia. O login vale 12 horas e só fica na aba do navegador; a chave em si nunca é guardada. A página `/admin` não aparece em buscadores (`noindex`).

**Autenticador (código de 6 dígitos no celular) — recomendado.** Em vez de depender só da chave, o painel pode pedir o código do aplicativo autenticador (Google Authenticator, Microsoft Authenticator, Authy, 1Password…), que muda a cada 30 segundos.
1. Entre no painel com a chave → aba **Sistema** → **Ligar o autenticador**.
2. No celular abra o aplicativo, toque em **+** e **escaneie o QR Code**. Se estiver abrindo o painel **no próprio celular** (não dá para escanear a própria tela) ou sem câmera, use os botões da janela: **Abrir no app autenticador** (abre o aplicativo já com a conta pronta), **Copiar chave** (depois: **+** → *Inserir chave de configuração* → colar) ou **Enviar pelo WhatsApp** (abre o WhatsApp com a chave pronta para mandar; escolha a conversa com você mesmo). Depois de ligar, **apague a mensagem** do WhatsApp: quem tiver a chave gera os seus códigos. Para o botão já abrir direto a sua conversa, defina no servidor `ADMIN_WHATSAPP` com o seu número (ex.: `11999990000`; o 55 é acrescentado sozinho). O número fica só na variável do servidor, nunca no código, e só aparece para quem já está dentro do painel.
3. Digite o código de 6 dígitos que o app mostrar, escolha como quer entrar e toque em **Ligar**:
   - **Chave + código** (mais seguro, recomendado): o painel pede a `ADMIN_KEY` **e** o código. Deixe a chave salva no gerenciador de senhas do navegador e digite só o código.
   - **Só o código** (mais prático): a chave deixa de ser pedida. Por segurança, **5 códigos errados seguidos travam o painel por 15 minutos**.
- Cada código vale **uma vez só** (se acabou de entrar, espere o próximo para repetir) e é guardado no servidor sem aparecer em nenhum registro. Ligar ou desligar pede o código e encerra as outras sessões abertas.
- Com o autenticador ligado, a chave sozinha **não abre mais nada**, nem as rotas de scripts (`x-admin-key`): só uma sessão do painel. Tudo fica na **Auditoria** (`ligou-autenticador`, `desligou-autenticador`, `login`, `login-falhou`).
- **Perdeu o celular?** No servidor (Render → **Environment**, ou o `.env` do seu computador), crie `ADMIN_2FA_OFF=1` e reinicie: o painel volta a pedir só a chave. Entre, **desligue e ligue o autenticador de novo** com o celular novo (a aba Sistema avisa enquanto a variável existir) e depois **apague** a variável `ADMIN_2FA_OFF`. Por isso, quem controla o servidor controla o acesso: guarde bem o acesso ao Render.
- Para o código funcionar, o relógio do celular precisa estar no horário automático (o servidor aceita até 30 s de diferença).

**O que o painel faz**
- **Visão geral:** quantos se cadastraram (hoje, 7 e 30 dias), quantos estudaram hoje, lições concluídas, provas, XP total, gráfico dos últimos 30 dias, funil de cadastro, últimos cadastros, ranking de XP e quantos estão em cada curso; avisa quando algum curso está desativado.
- **Usuários:** lista de todos com busca por nome/e-mail, filtros (já estudaram, nunca estudaram, ativos/sumidos, e-mail sem confirmar, Google, curso liberado, suspensos), ordenação, páginas e **baixar CSV** (abre direto no Excel).
- **Ficha do aluno** (clique na linha): progresso por curso e nível, atividade recente, aparelhos logados e as ações:
  - **Liberar curso** (Python, SQL ou **todos os cursos**) para aquela pessoa: tira os bloqueios de nível, de sequência e de checkpoint e já permite fazer as provas. **Liberar não aprova nenhuma prova de graça.** Dá para tirar a liberação quando quiser.
  - **A pessoa não precisa recarregar nem sair do app**: o app confere sozinho (ao voltar para a aba/app e a cada ~1 minuto, só no mapa, nunca no meio de uma lição ou prova) e destrava as lições na tela, com o aviso "Seus cursos foram liberados!". O mesmo vale para o *Modo livre* (ligar e desligar) e para os comunicados do dono.
  - Confirmar e-mail, reenviar confirmação, gerar link de nova senha, encerrar sessões, mudar nome, ajustar XP, zerar o progresso de um nível, anotação interna (só você vê).
  - **Suspender** (a pessoa é desconectada e não consegue entrar nem recuperando a senha; dá para reativar) e **Excluir conta** (só se você digitar o e-mail da pessoa).
- **Aprendizado:** as lições em que os alunos mais travam e as que mais exigem tentativas, e a taxa de aprovação de cada prova (para saber o que melhorar no conteúdo).
- **Ajustes:** **Cursos do aplicativo** (uma chavinha para cada curso: **ativo** ou **desativado**; desativado some da aba Cursos, da escolha do primeiro curso e dos Desafios, e fica bloqueado no servidor, até com o *Modo livre* ligado; o progresso e o XP dos alunos ficam guardados e voltam quando você reativa; pelo menos um curso precisa ficar ativo; quem estava num curso desativado cai na tela de escolher outro curso); **fechar/abrir cadastros**; **comunicado** para os alunos (aviso azul, verde ou amarelo no topo da tela inicial); **modo livre** (libera todos os cursos para todo mundo por 1, 7 ou 30 dias, ou sem prazo — bom para promoção ou demonstração).
- **Sistema:** confere banco de dados, e-mail, Google, anúncios, correção de Python e de SQL e o endereço do site, com dica do que falta.
- **Auditoria:** registro de tudo o que foi feito pelo painel (quem, o quê, quando e de qual IP). Nunca guarda senhas.

**Para scripts:** as rotas antigas continuam valendo com o cabeçalho `x-admin-key: <ADMIN_KEY>` (`GET /api/admin/stats`, `POST /api/admin/reset-link`) **enquanto o autenticador estiver desligado**; ligado, elas passam a responder 404. O painel usa `x-admin-token`, obtido em `POST /api/admin/login`.

**Painel em endereço separado (recomendado em produção).** O painel e o app dos alunos rodam no **mesmo servidor** — de propósito: o app guarda os dados em memória, então um segundo servidor mexendo no mesmo banco desatualizaria e até sobrescreveria o que o primeiro gravou (liberações e suspensões não valeriam). O que dá para separar é o **endereço**: o painel num subdomínio só seu, que não existe no site público.
1. No Render, abra o serviço → **Settings → Custom Domains** → adicione `admin.seusite.com.br` (além do domínio do site). No seu provedor de domínio, crie o registro **CNAME** `admin` apontando para o endereço que o Render mostrar (algo como `codeup.onrender.com`).
2. Em **Environment**, crie `ADMIN_HOST` = `admin.seusite.com.br` (só o endereço, sem `https://`) e deixe o Render reiniciar.
3. Pronto: `https://admin.seusite.com.br` abre direto o painel; no site público `/admin` e `/api/admin/...` passam a responder 404, e no endereço do admin só o painel funciona (o app dos alunos não abre ali). A chave `ADMIN_KEY` continua sendo a senha. Os links de "nova senha" que você gera continuam apontando para o site público.
Sem `ADMIN_HOST` (ou no seu computador) tudo fica no mesmo endereço, como antes. A aba **Sistema** mostra qual endereço está valendo.

O **Perfil → Expressões** tem um botão para cada pose (**18** para a Tay, **23** para o Cut; `EXPR` em `app.js`, nomes no feminino para a Tay e no masculino para o Cut). A cor escolhida em "Cor da roupa" vale nas poses (rotação de matiz em tempo de execução, `hueShift()` em `rewards.js`; a língua do Cut continua vermelha). As **estampas** da roupa **não** são aplicadas nas poses (só a cor). Se as poses não carregarem, ou sem WebGL, ou com "reduzir movimento" do sistema, o app cai no corpo animado/imagem normal.
  - **Comemorações por acontecimento e sons** (`okFx`, `passFx`, `streakFx` e `setFb` em `app.js`; `public/sfx.js`): **acertou** → tela "Acertou!" (ou "De primeira!" se foi na 1ª tentativa, ou "Combo ×N" com lições seguidas de primeira) com o XP ganho, raios, faíscas e o personagem comemorando, que passa sozinha em ~2 s (ou ao tocar) e dá lugar ao resultado da lição; **errou** → o aviso balança e a carinha do personagem aparece em cima ("ops!" quando o código dá erro, pensativo quando só não está certo); **prova aprovada** → troféu dourado com brilho, confete, personagem pulando e o botão Continuar (depois vem o resultado completo; "Trilha concluída!" quando é a última); **frequência** → na primeira lição do dia (o servidor devolve `streakUp` em `/api/submit`) aparece, por cima do resultado, a **chama** com o número de dias rolando e a semana com os dias feitos; os marcos (3, 7, 14, 30, 50, 100, 200, 365 dias) ganham cor dourada, confete e fanfarra. As sequências de poses dessas telas são os reels `ok`, `perfect`, `pass`, `streak` e `streak7` (em laço, `period: 'loop'`). Ao tocar, ele **acorda assustado e dá oi** (`ops` → `tchau` com o balão "Oi!"), o fundo esquenta e o botão vira "Bora estudar!". A tela só some de vez depois de acordar o personagem (`POST /api/away/ack`): recarregar a página antes disso não perde a tela. Também vale para o app aberto na memória do celular: ao voltar para ele depois de 30 min, ele confere de novo. Sem animação (movimento reduzido ou sem WebGL) aparece a imagem parada do personagem dormindo. No **modo teste** a faixa laranja tem o botão **Simular ausência** (`POST /api/teste/ausente`).
  - Cenário do mapa (`public/mapscene.js`): tudo é SVG desenhado no próprio arquivo (pinheiros, pedras, capim, moitas, cogumelos, flores, colina de musgo, lago, coruja dormindo, placa com a logo da trilha, lampião e vaga-lumes). `mapScene({ X, M, NR, track, cur, W })` devolve o HTML do cenário para o `app.js` colocar atrás da trilha: ele sorteia as peças com semente fixa (o mapa não muda de lugar a cada abertura), põe as peças grandes no lado livre de cada curva, evita a linha do caminho e deixa a lição do momento (`cur`) livre para o personagem e o cartão. Para mudar um desenho, edite a função dele no arquivo (`pine`, `ROCKS`, `bush`, `POND`, `OWL`, `SIGN`, `LAMP`…); para mudar o clima, as cores ficam nos gradientes `ms…` do `DEFS`. O estilo (pedestal, cartão da lição, animações) está no fim do `style.css`. Nos outros visuais o mapa continua como antes.
  - Logos dos cursos: `public/img/logo-python.webp`, `logo-sql.webp` e `logo-excel.webp` (fundo transparente) aparecem em todas as telas pela função `tg()` do `app.js`. Para trocar, coloque a nova imagem (as duas logos lado a lado, fundo branco) em `tools/anim/src/logos-python-sql.png` e rode `python3 tools/anim/logos.py`; o script tira o fundo, separa as duas logos pelo espaço vazio no meio e regrava os `.webp`. Se mudar o nome do arquivo, lembre de atualizar a lista `SHELL` do `sw.js`.
  - Para trocar ou acrescentar poses: `python3 tools/anim/pacote.py` (precisa de numpy, opencv, pillow, scipy e scikit-image) lê as folhas `tools/anim/src/tay-expressoes.png` e `cut-expressoes.png` (PNG com fundo transparente), separa cada pose (as que se encostam são divididas por *watershed*), recorta os rabiscos, amplia ×2, leva as cores para a paleta do app e regrava os `.webp` e o `poses.js`; `--prev` salva folhas de prévia e a imagem da segmentação em `/tmp`. Se trocar as folhas, confira no topo do script `CELLS` (um ponto dentro do corpo de cada pose), `EXTRA` (pontos extras num pé que encosta na pose de baixo), `ROUTE` (rabiscos que ficam entre duas poses), `KEEP` (pedaços soltos que fazem parte do corpo, como as lágrimas do Cut), `KIND` (pose de corpo inteiro ou sentada/deitada) e `ALIAS`.
  - Um único contexto WebGL fora da tela desenha em vários `<canvas>`; tudo pausa quando a aba está escondida ou o personagem sai da tela. As **estampas** (listrado, bolinhas, xadrez, degradê, estrelas, camuflado, tie-dye, galáxia, dourado e holográfico) são calculadas no shader sobre a imagem original e mantêm as sombras do tecido; cada estilo pede um título (`OUTFITS` em `public/rewards.js`, `id` é o número que o shader entende). As máscaras ficam em `public/img/<guia>-parts.png` (R moletom, G calça, B tênis), `-rig.png` (R cabeça, G cabelo, B braço) e `-eye.png` (olhos); os scripts que as geram estão em `tools/anim/`. Para um personagem novo: imagem 640×960, as três máscaras e uma linha em `CH` no `anim.js` (pivôs e olhos).

## 6) Segurança e privacidade já incluídas
**Contas e sessões:** senha com hash (scrypt), mínimo de 8 caracteres e lista de senhas comuns recusadas · login em tempo constante (não revela se o e-mail existe) · limite de tentativas por IP **e por conta** · sessões de 60 dias, no máximo 10 por pessoa, guardadas **só como hash** no banco (se o banco vazar, ninguém entra nas contas) · trocar/recuperar senha derruba os outros aparelhos · links de redefinição e de confirmação de e-mail: aleatórios, de uso único, guardados com hash · login com Google verificado no servidor.
**Regras do curso e pagamento:** tudo imposto no servidor (provas, sequência das lições, cursos ativos) · gabarito nunca vai ao navegador na prova · SQL e Python do aluno corrigidos em ambiente isolado, com tempo e memória limitados e fila com teto.
**Navegador:** Content-Security-Policy (só carrega código do próprio site, do CDN do Python e do login do Google; bloqueia plugins, iframes de terceiros e `<base>`) · HSTS · X-Frame-Options · Permissions-Policy · nada de `eval` de dados do usuário; todo texto do aluno é escapado · sql.js servido pelo próprio site · o service worker nunca guarda dados da API nem páginas privadas · não usa cookies (o token vai em cabeçalho), então não há CSRF.
**Produção:** com `NODE_ENV=production` (o Dockerfile já define) as flags de teste `DEV_SHOW_RESET_LINK`, `ADS_PREVIEW` e `RELAX_SUBMIT_LIMIT` são **ignoradas** e links/tokens nunca vão para o log · dependências sem vulnerabilidades conhecidas no `npm audit` (rode de novo de vez em quando).
**Privacidade (LGPD):** aceite dos Termos, baixar os dados e excluir a conta.
**O que depende de você:** HTTPS (o Render já dá), `BASE_URL` com `https://`, chaves reais só nas variáveis do servidor (nunca no GitHub), `ADMIN_KEY` longa, e-mail configurado, e deixar **uma só cópia** do servidor rodando. Se hospedar sem proxy (VPS direto), o IP vem de um cabeçalho que o cliente pode forjar: use um proxy como o Caddy/Nginx ou o Cloudflare na frente.

## 7) Antes de divulgar (importante)
- **Termos e Política:** são modelos. Leia, ajuste e, de preferência, peça a um advogado para revisar (CPF/CNPJ, endereço, política de reembolso).
- **Limites conhecidos:** (1) o isolamento do Python é feito por várias travas (processo separado, ambiente vazio, limites de CPU/memória, bloqueio de rede, arquivos e subprocessos), mas não é um contêiner dedicado: para uma escala grande, rode a correção em um serviço separado sem acesso ao banco; (2) o servidor mantém os dados em memória e deve rodar em uma única cópia; (3) o aluno que digita a resposta pronta (ex.: `print("Olá, mundo!")`) passa nas lições, porque o gabarito aparece na correção ao vivo; nas provas o gabarito não aparece; (4) o curso “Dashboards e Visualização” aparece como “Em breve”; (5) o Python do navegador (Pyodide) e o do servidor podem ter versões diferentes de pandas: as atividades usam só saídas simples para evitar divergência.
- **Pandas:** as lições de Pandas (Python Avançado, 21 a 30) baixam ~15 MB na 1ª vez (depois ficam em cache).
